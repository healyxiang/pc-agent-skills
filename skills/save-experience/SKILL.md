# Save Experience - 经验提炼器

将当前对话中的技术经验、问题排查过程、解决方案提炼为结构化的可复用文档。

## 使用流程

### Step 1: 分析对话内容

回顾整个对话，识别以下要素：

- **核心问题**：遇到了什么问题或需求
- **关键决策**：做了哪些技术选型或方案取舍
- **解决路径**：从问题到解决经历了哪些步骤
- **踩坑记录**：哪些方案不可行，为什么
- **最终方案**：最终采用的解决方案是什么
- **相关知识**：涉及的技术栈、API、工具、配置

### Step 2: 判断分类

根据内容选择合适的分类目录：

| 分类 | 目录名 | 适用场景 |
|------|--------|----------|
| 问题排查 | `debugging/` | Bug 修复、错误排查、性能调优 |
| 配置指南 | `configuration/` | 环境搭建、工具配置、CI/CD 设置 |
| 架构设计 | `architecture/` | 技术选型、架构决策、系统设计 |
| 编码技巧 | `coding-tips/` | 代码模式、最佳实践、语言特性 |
| 工具使用 | `tooling/` | CLI 工具、IDE 插件、开发工具链 |
| 部署运维 | `devops/` | 部署流程、容器化、监控告警 |
| 其他 | `misc/` | 不属于以上分类的内容 |

### Step 3: 生成文档

使用以下模板生成 Markdown 文档：

```markdown
# [简明标题]

> 📅 日期: YYYY-MM-DD
> 🏷️ 标签: #tag1 #tag2 #tag3
> 📂 分类: [分类名]

## 问题背景

[用 1-3 句话描述遇到的问题或需求]

## 关键信息

- **环境/版本**: [相关技术栈和版本]
- **错误信息**: [如有，记录关键报错]

## 解决方案

[核心解决步骤，用编号列表]

1. ...
2. ...
3. ...

### 关键代码

[如有关键代码片段，附上]

## 踩坑记录

[记录走过的弯路，避免重复踩坑]

- ❌ 方案A 不可行，因为...
- ❌ 方案B 不可行，因为...

## 经验总结

[提炼 2-5 条可复用的经验]

- ✅ ...
- ✅ ...

## 参考链接

- [相关文档或链接]
```

### Step 4: 保存文档

默认保存路径: `~/knowledge-base/{分类}/{文件名}.md`

文件名规则：
- 使用小写英文 + 连字符
- 简明扼要地描述主题
- 例如: `fix-node-memory-leak.md`、`setup-docker-multi-stage.md`

执行保存：
1. 确保目录存在: `mkdir -p ~/knowledge-base/{分类}`
2. 写入文件
3. 输出保存路径，确认完成

## 注意事项

- 文档应**自包含**，脱离对话上下文也能看懂
- 代码片段只保留**最关键的部分**，不要整段复制
- 踩坑记录和经验总结是最有价值的部分，重点提炼
- 标签有助于后续检索，至少添加 3 个
- 如果一次对话涉及多个不相关的经验点，拆成多个文档保存

## 输出确认

保存完成后，输出：

```
✅ 经验文档已保存
📄 路径: ~/knowledge-base/{分类}/{文件名}.md
🏷️ 标签: #tag1 #tag2 ...
📝 摘要: [一句话摘要]
